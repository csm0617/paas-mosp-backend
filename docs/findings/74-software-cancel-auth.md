# `POST /v1/software/cancelAuth`：五种情形对拉一致（含一处**非原子**行为）

**证据等级**：〔运行实测〕（探针行 + 逐情形对拉 + 库内状态核对）+〔代码事实〕。2026-10-14。

## 1. 实测（每种情形前都**重置探针行**，两侧各打一次，并核对库内状态）

| 情形 | code | data | msg | 库内 `pc-1` 状态 |
| --- | --- | --- | --- | --- |
| 有激活码 | 0/0 | **相同** `[{softwareKey:probecancelA, result:false}]` | OK | `NULL\|NULL` / `NULL\|NULL` ✅ |
| 无激活码（一个都没取消到） | 400/400 | （trace 不同） | 「没有软件获得授权，无法进行取消授权操作」 | **未改动** ✅ |
| 混合（一个有、一个无） | 0/0 | **相同**（只返回一项） | OK | 已清空 ✅ |
| 不存在 | 400/400 | （trace） | 「软件不存在或被删除无法进行取消授权」 | **未改动** ✅ |
| 先有效、后不存在 | 400/400 | （trace） | 同「不存在」 | **已被清空** ✅（两侧一致） |

**比较口径**：`code` + `msg` + `data`（**忽略 `trace`**，见 `findings/72` 的方法清单）+ 库内状态。

## 2. 两处照抄点

1. **没有激活码的软件是"跳过"，不是"报错"** —— 它不产出结果项；只有当**结果列表为空**时才是
   400 `auth.no.software.authorization`（即"一个都没取消到"是错误，不是空数组）。
2. **这条链路没有事务**：最后一行那条用例（先有效、后不存在）实测**两侧库里都已被清空**——
   先清空、再抛错，**清空不回滚**。这是厂商的既有行为，我们照抄；它属于"该记下来的粗糙"，
   不是我们引入的。

## 3. 又踩了一次"引号会改我的命令"（这次是 shell）

第一版验证脚本用 `python3 - <<PY`（**未加引号**的 heredoc）—— 里面的 SQL 含**反引号**（`` `key` ``），
被 **shell 当成命令替换**执行了，于是 `reset()` 静默失效：库没被重置、两侧看到的状态不同，
输出看起来像"五条全不一致"。
改用 `<<'PY'`（**带引号**，禁止 shell 替换）后一切正常。

**教训**：这已经是"引号/转义"家族的第四次（python heredoc 嵌三引号 ×3、这次 shell 反引号 ×1）。
**规则**：任何含反引号/`$`/三引号的脚本，一律用**带引号的 heredoc**或独立脚本文件，
并且**在跑之前确认它真的执行了**（这次是"库里状态完全没变"暴露的）。
