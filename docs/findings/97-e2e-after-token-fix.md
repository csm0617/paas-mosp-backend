# e2e 复验（第 91 轮）：改了 `/v1/user` 的 token 之后，厂商原样前端**页面仍然与厂商一致**

**证据等级**：〔运行实测〕（厂商原样前端 + 我们的后端，并与归档的厂商页面逐项比对）。2026-10-14。

## 1. 为什么要专门跑这一次

第 89 轮我把 `GET /v1/user` 的 `data.token` 从"会话 token"改成了 **null**（B11 修复，为了与厂商一致）。
**`/v1/user` 正是前端用来拿当前登录用户的端点**——如果前端读 `data.token`，这一改就可能让页面失效。
"厂商也返回 null"只能说明**厂商前端**不依赖它，不能说明**我们的实现**没被改坏（两侧的会话/装配路径不同）。

⇒ 所以做一次针对性 e2e 复验。

## 3. 结论

- B11 的修复**没有破坏前端**：用户管理页仍然与厂商一致（表头/数据行/可见文本全等）；
- 顺带再次确认第 68 轮建立的"复验流程"可重放（临时 Redis NodePort → 起后端 → 单次登录 → harness → 驱动 Chrome → 比对 → 清理）；
- **这条经验值得复用**：**改动了前端会读的端点，就必须重跑 e2e**——契约比对（L1/L2）只看"字段对不对"，
  看不出"页面会不会白屏"。
