## 三、已记录的偏离与未定论（交接时必须带走）

1. **L2 允许偏离 2 条**（在 `read-paths.json` 里，需追认）：`restartCount`（前端 `|| 0` 显示等价）、`mappingInfo`（我们恒返回三键对象，厂商 4/9 行返回 null）。
2. **L3 已知偏离 3 条**：`runningDeployment`（厂商运行态 0、按规则应为 5）、client-java 的显式 null 与自造键 `proxy`、fabric8 多出的 4 个新 K8s 字段。
3. **页面「镜像」列显示 `undefined/undefined` 是前端怪癖，不是我们的缺口**（本轮查清）：前端 `render` 做 `image.split("/")` 后取 `parts[1]/parts[2]`，要求镜像串是 `registry/repo:tag` 三段；本环境镜像是 1–2 段（`gaop-be:V1.3.4-…`、`system_containers/gaop-auth:0.0.3-arm64`），**厂商自己的样本同样会显示 `undefined`**；我方返回的镜像串与厂商逐字一致。
4. `/software/workloads` 内容区为空：**厂商在同一条 harness 下也一样**（`docs/findings/20`），根因未定论（候选：headless 环境、引导弹窗状态、页面自身前置）。
5. `404 /api/gaop/register/ip/harbor`（Harbor 注册 ping）、SockJS 的 `/ws/iframe.html`（无害）。
6. Harbor / Loki / 镜像仓属**另一域**，未接管。

## 五、怎么继续（复现与运行）

```bash
# 1) 离线测试（无需集群）
mvn test
# 2) 需要集群时：MySQL 走 NodePort，Redis 需临时暴露（用完删除）
kubectl -n gaop-namespace expose deploy gaop-redis --type=NodePort --name=gaop-redis-tmp --port=6379
MYSQL_HOST=172.16.209.25 MYSQL_PORT=30306 REDIS_HOST=172.16.209.25 REDIS_PORT=<np> \
  java -jar paas-core-app/target/paas-core-app-1.0.0-SNAPSHOT.jar
# 3) 真实前端 e2e
TOK=$(curl -s -D - -o /dev/null -X POST http://127.0.0.1:8080/v1/pub/login -H 'Content-Type: application/json' \
      -d '{"username":"admin","password":"admin123","role":"admin"}' | sed -n 's/.*gateway-token=\([^;]*\).*/\1/p' | tr -d '\r')
GAOP_TOKEN=$TOK DIST=/Users/csm/Desktop/Project/msop/build/gaop-web-ctx/html node tools/frontend-e2e-harness.mjs 8099
# 4) 契约比对
python3 tools/contract-check.py "GET /v1/service"
```

**注意事项**（都是踩过的）：
- 单点登录（`max-login=1`）：两个 harness **不能同时**持有同一 (用户,战位) 的会话，A/B 要顺序跑；每次起 harness 前现取 token 并先 `curl /v1/user` 验一次。
- `page.setCookie` 对 IP 主机名必须用 `url` 而不是 `domain`。
- 打开页面用 `domcontentloaded` + 固定等待，`networkidle2` 会被 SockJS 重试拖住。
- 播种 MySQL 必须带 `--default-character-set=utf8mb4`（否则中文双重编码，见 `docs/findings/11`）。
