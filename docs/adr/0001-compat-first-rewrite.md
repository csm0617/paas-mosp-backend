# 目的地是"可替换重写"，兼容优先

**Status: accepted**

厂商后端 gaop-be 有 1598 个类、约 604 个 handler；厂商前端 gaop-web（196 个 service 函数、95 条路由、三套语言包）与 87 个 Flyway 迁移（39 张表）已经把接口与数据模型固定成既成事实。我们决定：重写以**替换厂商后端**为目的，保持 `/api/gaop/v1/*` 契约与现有 DB schema 兼容，前端一行不改；不采用"重定接口与表结构的自研版"。

## Considered Options

- **兼容替换（选中）**：前端与 schema 不动，重写只换实现。代价是背着历史包袱（新旧命名混用、`Tenx*` 遗留命名）。
- **自研业务模型版**：允许改接口与表结构。被否——会让已复刻出的前端证据与 87 个迁移全部作废。
- **只交方案不落地**：被否——得不到"跑得起来"的反馈，无法验证 DDD 分层与 fabric8 换装是否真的成立。

## Consequences

- 前端复刻产物（`../recovered-web/`）从"待迁移资产"变成**验收工具**：契约比对的另一端。
- 重写后仍要保留一批历史命名（`Tenx*`、`com.glriverside.gaop` 包名），这是刻意的，不要"顺手美化"。
- 任何意图改动响应形状或表结构的提案，都必须显式挑战本 ADR，而不是悄悄改。
